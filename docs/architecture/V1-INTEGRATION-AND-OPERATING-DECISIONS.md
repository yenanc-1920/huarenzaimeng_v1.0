# V1 外部集成与经营决策基线

状态：`CONFIRMED_REQUIREMENT_WITH_IMPLEMENTATION_GAPS`
适用范围：V1 的微信登录、微信支付、WINLA 充值、A130 定价、手机号处理和后台权限。
证据边界：本文记录已确认的产品/经营决策，并明确区分候选代码现状；它不证明真实微信、WINLA 或生产运行已经通过。

## 1. 微信 AppID 四环境策略

- DEV、TEST、STAGE、PROD 共用同一个已经获批的小程序 AppID。
- 四环境必须继续使用独立的云托管服务、数据库、数据库账号和 Secret；共用 AppID 不等于共享数据或凭据。
- AppSecret 由平台按环境单独配置，禁止进入 Git、日志、截图和本次环境 JSON 汇总。
- AppID 同样不写入本次四环境 JSON；配置清单只标记其为平台侧受控输入。
- 登录成功结果必须校验返回 AppID 与当前环境预期 AppID 一致；支付通知必须绑定预期 AppID、商户号和允许的平台证书序列号。
- 未配置、错配或适配器不可达时必须失败关闭，不允许生成 Fake 成功结果。

候选现状：微信身份和支付已经有正式端口、绑定校验和 Disabled 默认实现；真实传输适配器、平台秘密装载和真机验收仍属于外部输入，不能从环境模板推断为完成。

## 2. WINLA 充值契约

### 2.1 金额与币种

- 本地订单金额使用整数 minor unit 和显式三位币种；供应商原始金额、币种必须以不可变 raw 字段保存。
- raw 金额只接受非负十进制文本，按冻结的供应商 scale 使用 `UNNECESSARY` 精确转换；前导零可规范化，额外小数、溢出、非数字、币种错配均进入 `UNKNOWN`，不得判定成功。
- 适配器是 raw 到 canonical 的唯一转换边界；协调器只消费已经验证的 canonical 金额和币种。
- 同一 provider request 或 provider reference 的不同参数必须冲突关闭，不能覆盖历史事实。

### 2.2 状态与查询

- 仅映射 `SUBMITTED`、`PROCESSING`、`DELIVERED/SUCCESS`、`REJECTED/FAILED`；未知状态保持 `UNKNOWN`。
- `DELIVERED`、`REJECTED` 为终态，禁止互相覆盖；`UNKNOWN` 只能按有限预算和截止时间查原单，禁止再次提交充值。
- `UNKNOWN` 持续占用余额和渠道/运营商在途额度；拒绝时释放，成功时结算；预算耗尽或过期转人工交易差异，不自动重充或退款。

### 2.3 回调与绑定

- 回调必须先由适配器验签，再绑定 merchant order、provider ref、SKU、recipient digest、原始金额和币种。
- 任一字段缺失、无法精确映射或与提交快照不一致时保持 `UNKNOWN`；不得用供应商“成功”文本越过绑定校验。
- 回调收件、状态单调推进、余额释放和业务事件必须幂等；重复回调只产生一个业务事件。

### 2.4 孟加拉号码

- 接受本地 `01xxxxxxxxx`、`8801xxxxxxxxx` 和 `008801xxxxxxxxx` 形式，统一规范为 `8801[3-9]xxxxxxxx`；其他号码拒绝。
- 供应商提交使用受信订单权益快照中的号码、SKU、金额和币种，不接受客户端自报。
- 真实 WINLA 字段名、签名 canonical 串、scale、回调字段和应答协议尚未取得书面合同，因此真实适配器保持 `NO_GO_REAL_PROVIDER_CONTRACT`。

候选现状：供应商无关协调、金额规范化、状态机、回调绑定、余额/限额和恢复任务已存在；生产 Bean 当前仍固定装配 Disabled WINLA 端口，没有环境变量可把它安全地切到真实网络。

## 3. A130 定价草稿默认值

以下值仅用于 A130 “新建草稿/试算”的界面预填，不是后端隐式默认，也不得自动启用价格：

| 字段 | 冻结预填值 |
|---|---:|
| 成本缓冲 `bufferRate` | `0` |
| 平台上浮 `markupRate` | `0.10` |
| 固定上浮 | 不启用 / `0` |
| 微信支付费率 `wechatFeeRate` | `0.006` |
| 税费预留 `taxRate` | `0` |
| 最低毛利金额 | `0` |
| 最低毛利率 `minimumMarginRate` | `0` |
| 舍入 `roundingRule` | `CEILING_0_01`（向上取整到分） |
| 促销承担 `promotionBearer` | `NONE`，分摊 `0` |
| CNY→CNY 汇率 | `1` |

- 后端仍要求 `SUPER_ADMIN` 显式提交完整输入，使用持久化 supplier catalog item 成本和 FX 快照试算。
- 不信任请求自报 supplier cost；未绑定商品、成本或汇率漂移时失败关闭。
- V1 不走财务审批；启用前仍执行最低毛利、时间区间、渠道映射、版本和重叠价格校验。
- 历史订单使用下单时价格/权益/汇率快照，不追溯后续价格调整。

候选现状：数据库字段默认仍为 `NULL`，后端不存在上述数值的静默 fallback；这是有意的安全边界。

## 4. V1 完整手机号明文决策

- V1 允许数据库保存完整手机号明文，以满足真实充值履约。
- 明文只允许进入履约专用字段/表，并采用最小权限访问和明确保留期删除。
- 后台、普通 HTTP 响应、日志、异常、审计、outbox 和业务事件只允许 mask 或不可枚举 HMAC/digest，不得返回或复制 raw 手机号。
- 报价/订单公共快照继续保存 mask + 独立 Secret HMAC；HMAC Secret 每环境独立，缺失时失败关闭。
- 后续版本迁移到 KMS/密文存储，迁移前不得声称当前方案达到静态加密。

候选差距：现有充值协调中仍存在 `recipient` 持久字段，需要在真实上线前完成“履约专表、访问收口、保留期删除和全出口扫描”验收。该决策是已确认需求，不代表候选代码已经完全达标。

## 5. `SUPER_ADMIN` 初期单账号例外

- 初期唯一 `SUPER_ADMIN` 账号允许对同一内容对象完成创建、提交、审核和发布。
- 这是显式例外；其他 `CONTENT_OPERATOR` 与 `CONTENT_REVIEWER` 继续执行四眼职责分离。
- 例外不得绕过 `expectedVersion`、`Idempotency-Key`、审核原因、状态机、定价计算或审计。
- 审计应记录 `selfApproved=true` 和 `exceptionPolicyVersion`，便于增加第二个账号后关闭例外。
- 价格/渠道/真实能力启用仍只允许 `SUPER_ADMIN`，不因内容例外下放。

候选差距：当前服务层仍禁止提交者审核、并禁止发布者与提交者/审核者相同，因此该例外尚未实现；上线前必须由实现、安全和测试共同验收，不能仅通过改角色名称绕过。

## 6. 默认关闭原则

- 微信真实身份、微信支付、WINLA 充值、恢复 scheduler、测试只读、fixture、sandbox 和 synthetic 均默认关闭。
- 任何外部能力必须同时满足：冻结协议、独立环境秘密、正式适配器、回调权威校验、失败关闭测试和一次明确授权的小额实测。
- 环境变量“存在”不等于功能已获准；没有正式 Bean 的能力不得通过添加一个猜测变量启用。
