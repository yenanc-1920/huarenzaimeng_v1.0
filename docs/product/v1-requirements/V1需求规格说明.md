# 华人在孟 V1 需求规格说明

> 隔离候选交付副本。状态：需求确认稿。更新时间：2026-08-18。
> 原型基线：`项目管理/V1页面原型/业务流程/v1-business-flow-baseline.html`、`business-flow-data.js`、`BASELINE.md`。
> 本文描述 V1 应达到的产品行为，不代表当前代码、第三方资质或生产环境已经完成。

## 0. 2026-08-18 冻结补充

- 登录前《用户协议》和《隐私政策》使用两个独立勾选项，初始均为未勾选；两项同时勾选后，才进入微信官方隐私授权与 `wx.login` 流程。任一项未同意或官方授权被拒绝时，不创建平台会话。
- “我的”固定提供《用户协议》《隐私政策》查看、退出登录和注销账号。注销需要二次确认；存在进行中订单、UNKNOWN 支付/充值/退款、未结客服案件或交易差异时失败关闭并展示处理入口。
- V1 仅允许唯一 `SUPER_ADMIN` 账号由同一人完成提交、审核和发布；这是首版受控例外，所有动作仍须独立留痕、记录版本和时间。除该唯一账号外，提交、审核、发布继续职责分离，任何角色不得改写权威交易终态。
- V1 充值手机号按订单受控字段明文保存，以支持真实充值、原单查询、退款和争议处理；用户端与普通后台默认脱敏，日志、业务事件、错误响应禁止输出完整号码。KMS/字段级密文列入后续版本，不作为 V1 上线的伪完成项。
- 定价初始默认值冻结为：汇率缓冲 `0%`、平台加价 `10%`、固定加价 `¥0`、微信支付费率 `0.6%`、税费 `0%`、最低毛利额 `¥0`、最低毛利率 `0%`、舍入 `CEILING_0_01`、促销模式 `NONE`、促销分摊 `0%`；`CNY/CNY` 的 FX 固定为 `1`。默认值仍需形成版本，只有 `SUPER_ADMIN` 可试算并启用。
- WINLA 继续遵守《V1真实充值供应商技术设计》：提交“受理”不是成功；查询 `1/2/3` 与回调 `200/201/202` 先在适配器内映射，回调必须验签且幂等；UNKNOWN 只查原单，不自动重充、自动换渠道或自动退款。金额单位/币种、回调应答、状态权威关系和孟加拉号码格式在供应商书面确认前保持 `NO-GO` 真实充值。

## 1. 产品目标

V1 核心是孟加拉手机号的余额、流量、套餐充值闭环：识别号码和运营商、选择商品、生成锁价报价、创建订单、微信支付、向真实充值供应商提交、展示终态、处理退款与交易差异。

V1 正式上线必须具备真实微信支付和真实供应商充值；黄页、节假日、生活资讯及微信客服作为辅助功能同步上线。小程序与运营后台均使用真实开发库/API 样例数据，页面不得展示“开发样例”“目录快照”或内部英文状态码。

## 2. V1 范围与排除项

### 2.1 包含范围

- 微信小程序：首页、充值交易、订单、找回历史订单、我的、微信客服、黄页、生活资讯。
- 运营后台：客服案件、交易差异、内容审核、黄页、城市、节假日/周休、资讯、供应商目录、商品、渠道/运营商、定价、订单/支付/充值/退款只读查询。
- 微信能力：`wx.login code` 换取平台买家会话、微信头像昵称授权展示、微信支付、关联微信客服会话。
- 充值供应商：通过正式签约且已启用的供应商 API 获取目录并提交充值；供应商尚未确定时保持不可售。
- 价格：供应商成本币种换算成人民币，叠加已配置费用和平台加价，形成有版本的最终售价。
- 数据治理：订单价格快照、权威支付/充值事实、可审计操作记录和失败关闭。

### 2.2 明确排除

- 不直连孟加拉本地运营商；不把候选供应商或人工样例冒充已接入渠道。
- 不在客户端手工修改支付、充值、退款终态；不自动重复扣款、重复充值或因未知状态自动退款。
- V1 不自动同步微信客服聊天全文；客服沟通后人工建单，或由系统异常自动建单。
- 微信客服不设小程序内二级页面，点击后直接打开小程序关联客服会话。
- 资讯详情不按城市或地域限制访问；黄页不做广告、推荐或担保。
- V1 不建设黄页、资讯、节假日或商品的业务图片资源能力：不提供封面图、机构图片、节日配图、商品图片、图片上传、素材库、图片排序、图片版权管理或对象存储接入；相应页面仅使用结构化文字和应用内置图标。该能力延期到后续版本，届时另行评审存储、审核、版权和兼容方案。
- V1 不引入复杂定价审批流；有权限人员试算后直接启用，但保留版本和审计。
- 不实现真实资金/充值“沙箱替代物”作为生产流程；Fake 仅允许自动化测试使用且不得进入生产制品或页面。

## 3. 角色与权限

| 角色 | 主要权限 | 禁止事项 |
|---|---|---|
| BUYER | 登录、查看可售商品、报价、下单、支付、查看本人订单、申请找回、浏览黄页/资讯、打开微信客服 | 访问他人订单；修改交易事实；调用后台接口 |
| CUSTOMER_SERVICE | 查询核验用户/订单、创建和跟进客服案件、追加备注/证据引用、转派/升级 | 覆盖已提交事实；修改支付/充值/退款权威结果 |
| CONTENT_OPERATOR | 维护黄页、城市、节假日、周休、资讯及商品展示文案；提交内容审核 | 启用价格；修改交易事实 |
| CONTENT_REVIEWER | 审核/驳回/下架黄页、节假日、资讯和商品展示内容 | 审核或启用价格；修改交易事实 |
| SUPER_ADMIN | 上述后台能力；配置渠道、目录映射、商品；定价试算和启用；关闭已满足条件的交易差异；唯一账号可按 V1 受控例外同人提交/审核/发布 | 绕过必填配置；重写权威交易事实；覆盖历史版本 |

开发环境及 V1 生产环境中，价格版本、供应商渠道和平台商品的最终启用仅允许 `SUPER_ADMIN`。唯一 `SUPER_ADMIN` 账号可以同人提交、审核和发布，但每一步必须保留独立审计记录；其他角色仍须职责分离。后续若引入专门价格运营角色，须另行变更本文；当前不得默认授权。

## 4. 通用页面与状态规范

每个数据页面必须有以下状态，不能以空白页面代替：

| 状态 | 展示与动作 |
|---|---|
| 正常 | 显示最后更新时间和可执行动作；金额带币种，时间带时区或按用户本地显示 |
| 首次空 | 说明为什么为空并给出唯一下一步，例如“暂无订单，去充值” |
| 筛选空 | 保留筛选条件，提示“未找到匹配结果”，提供清除筛选 |
| 加载 | 骨架或明确加载提示；提交按钮防重复点击 |
| 可恢复失败 | 中文原因、重试按钮和请求编号；只读查询可有限重试 |
| 不可恢复失败 | 中文原因、客服入口或返回动作；支付/充值提交不自动重试 |
| 禁用 | 说明缺少配置、权限或依赖；按钮不可点击，不能仅以颜色表达 |
| 部分未知 | 明确展示“处理中/等待确认”，不得冒充成功或失败 |

所有写操作要求幂等键或一次性业务标识、服务端鉴权、审计日志。手机号、支付单号、供应商交易号在非必要场景脱敏。用户可见状态统一使用中文。

## 7. 登录、支付、充值与客服集成

### 7.1 微信登录

1. 小程序调用 `wx.login` 获取一次性 code。
2. 仅通过 HTTPS 将 code 发送到指定 CloudBase 服务。
3. 后端向微信 `code2Session` 验证，绑定本地买家身份，签发短期 Bearer。
4. Bearer 仅用于买家 API，服务端从 token 解析买家，不接受客户端传入 buyerId 代替鉴权。
5. code、session_key、Bearer 不写日志、不落客户端持久明文；失败必须重新获取 code。

头像昵称是展示授权，与登录身份分离；拒绝授权不影响登录和下单。V1 微信头像仅在当前客户端会话内临时展示，不写入后端数据库、不写日志、不进入业务素材系统；会话失效或未授权时回退到应用制品内置的默认头像。若后续要求跨设备保存头像，必须另行评审私有对象引用和用户撤回机制。

### 7.2 微信支付

- 订单创建后由后端生成支付意图，客户端仅拉起微信支付。
- 支付成功以微信服务端通知或主动查单为准；通知验签、金额/商户/订单绑定必须匹配。
- 支付意图、通知和查询均幂等；未知状态只查原单，禁止创建重复扣款。
- 退款由受控服务端流程发起并记录独立事实；V1 用户端不提供无条件自动退款按钮。

### 7.3 供应商充值

- 仅当支付已权威确认、订单未提交过充值且商品/渠道快照有效时，创建唯一充值意图。
- 向订单快照中的固定渠道提交一次；迁移失败、超时或结果未知不自动换渠道、不自动重充。
- 优先消费供应商 webhook；没有 webhook 时按受控间隔查询原交易。
- 供应商成功/失败/处理中映射为平台规范状态，保留原始响应摘要和供应商交易号，敏感信息脱敏。

### 7.4 微信客服与内部案件

- 所有客服按钮直接打开关联微信客服。
- V1 不自动同步聊天记录；客服沟通后按订单/申请/游客编号核验并创建内部案件。
- 系统发现交易异常可自动建单；后台管理员也可人工建单。三类来源必须可区分。

## 8. 商品目录与定价规则

### 8.1 目录归一化

供应商目录原始记录不可覆盖。平台从每个同步批次提取国家、运营商、原始 SKU、类型、权益、有效期、成本、结算币种和可用性，再映射为平台商品。一个平台商品可以绑定多个候选渠道，但一张已支付订单只使用下单时固定的渠道和 SKU 快照。

### 8.2 汇率

- V1 推荐并确认采用 ECB 免费汇率 API 作为基准来源；API 不提供时使用最近一个仍在有效期内的已成功汇率版本。
- 换算方向统一为“供应商结算币种 → CNY”。若 ECB 无直接货币对，使用 ECB 基准币种交叉换算并记录路径。
- 仅允许 ECB 同时覆盖结算币种和 CNY 时交叉换算；若供应商使用 ECB 不支持的结算币种，该商品保持不可报价/不可售，直至另行确认合规汇率来源，禁止自行抓取或人工猜测汇率。
- 拉取频率、有效期和超时阈值由 `SUPER_ADMIN` 在上线前录入，当前数值为“待录入”，不得由开发样例代填。
- 超过有效期或拉取失败且无有效版本时，停止生成新报价；不得静默使用未知汇率。已创建订单继续使用报价快照。

### 8.3 计算模型

统一计算顺序：

1. 供应商成本按生效汇率折算人民币；
2. 应用汇率缓冲；
3. 计入微信支付通道费和税费；
4. 应用单一“平台加价”（平台服务费/抽成与平台上浮已合并，避免重复利润）；
5. 扣除促销优惠并记录承担方；
6. 按舍入规则得到最终售价；
7. 校验最低毛利，未达到则禁止启用/报价。

各百分比必须配置“计费基数”，固定额必须配置币种。V1 新建价格版本使用下列已冻结初始值；它们仍须进入版本、试算和启用审计，不能绕过 `SUPER_ADMIN` 直接形成售价。

### 8.4 V1 定价初始默认值

| 配置项 | 初始值 |
|---|---:|
| 汇率缓冲 | 0% |
| 平台加价 | 10% |
| 固定加价 | ¥0 |
| 微信支付费率 | 0.6% |
| 税费 | 0% |
| 最低毛利额 / 最低毛利率 | ¥0 / 0% |
| 舍入 | `CEILING_0_01` |
| 促销模式 / 促销分摊 | `NONE` / 0% |
| CNY/CNY FX | 1 |

上述值是首版新建价格版本的默认输入，不是硬编码最终售价；历史订单继续使用下单时价格快照，不追溯。

## 10. 验收标准

### 10.1 功能验收

1. 使用真实开发测试数据完成“号码识别→三类商品→锁价→订单→微信支付→真实供应商充值→订单终态”全链；正式上线前在受控小额真实交易中验收。
2. 支付成功但充值未知时，用户看到处理中，后台生成交易差异；系统不重复扣款、不重复充值、不擅自退款。
3. 登录用户只能看到本人订单；重新登录自动恢复正常订单；异常历史订单可通过找回流程核验。
4. 微信客服所有入口直接打开客服会话；后台案件不声称自动拥有聊天记录。
5. 黄页城市与分类筛选正确，地址结构符合当地格式；节假日优先级正确；资讯不按地域限制。
6. 供应商目录同步后必须经归一化、映射、商品配置和价格配置才能可售。
7. 汇率或关键价格配置失效时停止新报价；已下单订单价格不变化。
8. 只有 `SUPER_ADMIN` 能启用价格版本、渠道和商品；所有操作有操作者、时间、前后版本。

### 10.2 状态与体验验收

- 本文第4节的正常、空、加载、失败、禁用、未知状态逐页有可验证页面状态。
- 所有用户文案为业务中文，不出现内部枚举、Fake、候选渠道或开发术语。
- 列表支持刷新和合理分页；重复点击写按钮不产生重复业务对象。
- 错误反馈包含可理解原因和请求编号，不显示 Secret、原始异常、SQL 或供应商敏感响应。

### 10.3 数据与安全验收

- 微信通知验签、Bearer 鉴权、后台角色鉴权、订单归属检查全部在服务端完成。
- 权威事实、目录批次、价格版本、订单快照和后台操作日志不可被普通编辑覆盖。
- 生产禁用本地 synthetic/mock 写接口；外部凭据只从受控 Secret 注入。
- 上线前必须完成第三方资质、真实回调域名、隐私政策、用户协议、ICP 展示和公安联网备案真实值替换。

## 12. 未决配置与推荐默认处理

## 13. 交给小U的设计约束

1. 只在当前唯一交互基线上做高保真视觉与字段标注，不另起信息架构或第二套原型。
2. 延续现有欢迎语、蓝色充值主卡、双时钟、今日状态和四栏底部导航的风格。
3. 小程序优先单手操作：主动作唯一、状态中文、金额突出、手机号脱敏、异常解释直白。
4. 为第4节每类状态提供组件标注；不能只画正常态。
5. 后台新增/编辑/详情必须画出真实字段、必填、来源、权限、状态和审计区域；按钮文案使用“查看/跟进”“交易差异”。
6. 商品、目录、价格三者视觉分区；价格试算必须逐项展示基数、输入、结果和来源。
7. 未决数值统一写“待录入”，候选供应商写“候选·不可启用/不可售”，不得用看似真实的比例或状态代填。
8. 所有调整回写同一基线并重新渲染现有流程图；不得用静态图片取代可维护源文件。
9. V1 页面不得展示业务封面、机构图片、节日配图、商品图片、图片占位或上传/素材管理控件；仅保留应用内置品牌图标和 P022/P024 的微信临时头像/默认头像。
