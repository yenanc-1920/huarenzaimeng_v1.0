# 微信小程序隐私保护指引与授权配置清单（候选）

文档状态：`CANDIDATE / 代码冻结后逐项复核`

## 一、登录与协议页面

登录页必须提供且默认不勾选：

```text
□ 我已阅读并同意《用户协议》
□ 我已阅读并同意《隐私政策》
```

- 两个协议在未登录状态可分别打开、滚动阅读和返回；两个勾选项初始均为未勾选。
- 任一项未勾选时不得调用登录、创建会话或隐私相关接口。
- 勾选后仍须根据微信返回的隐私授权状态执行官方授权流程。
- 用户拒绝自有协议或微信隐私授权时，不创建登录会话。
- 登录成功后记录：用户主体、用户协议版本、隐私政策版本、确认时间和来源；不记录微信临时代码或Secret。
- 协议版本发生实质变化时要求重新确认。

## 二、微信官方隐私机制

正式代码应按当前基础库能力核对并使用：

- `wx.getPrivacySetting`：判断是否需要隐私授权；
- `wx.openPrivacyContract`：打开微信平台配置的隐私保护指引；
- `open-type="agreePrivacyAuthorization"`或等价官方授权流程：同步用户同意；
- 隐私接口仅在官方授权成功后调用。

自有《隐私政策》不得冒充或替代微信后台的《小程序用户隐私保护指引》。体验版和正式版均须配置与实际代码一致的隐私声明。

## 三、待对照代码声明的信息类型

提交微信审核前，按正式依赖图逐项核对，禁止多报或漏报：

| 信息/能力 | 当前用途 | 配置原则 |
|---|---|---|
| 微信用户标识 | 登录、账号和订单归属 | 仅后端换取和保存必要标识，AppSecret不进入小程序 |
| 昵称、头像 | “我的”展示 | 可选；拒绝后使用默认头像和游客标识 |
| 用户填写的手机号 | 孟加拉充值 | 明示用途；不作为微信登录默认收集项 |
| 微信支付 | 支付和退款 | 仅订单确认后由用户主动触发 |
| 微信客服 | 首版唯一客服入口 | 使用官方客服组件，不展示私人微信号 |
| 网络请求 | 调用四环境后端 | 开发工具可切环境；生产包锁定PROD |

如正式代码新增位置、相册、文件、剪贴板、通讯录、设备标识或其他隐私能力，必须先更新隐私政策、微信后台指引和代码门禁，再进入审核；V1不得默认申请未使用权限。

## 四、“我的”页面固定入口

```text
账号与协议
├─ 用户协议
├─ 隐私政策
├─ 退出登录
└─ 注销账号
```

- 用户协议、隐私政策始终可查看。
- 退出登录立即撤销本地和服务端会话，不删除交易事实。
- 注销账号执行待办检查、二次确认、会话撤销、删除/匿名化和法定记录隔离。
- 存在进行中订单、UNKNOWN支付/充值/退款或未结案件时，展示具体原因和处理入口，不静默失败。

## 五、协议版本

首版建议：

```json
{
  "userAgreementVersion": "2026-08-28-v1",
  "privacyPolicyVersion": "2026-08-28-v1",
  "effectiveDate": "2026-08-28"
}
```

版本号属于公开业务配置，不属于Secret。用户确认记录必须绑定版本，不能只保存一个布尔值。

## 六、发布前门禁

- [ ] 运营主体、统一社会信用代码、地址、邮箱与微信后台一致。
- [ ] 两份协议无占位符、无开发样例、无错误供应商主体。
- [ ] 微信后台声明的信息类型与正式代码实际调用完全一致。
- [ ] 登录前协议默认未勾选，拒绝路径不创建会话。
- [ ] 官方隐私授权拒绝路径不调用受限接口。
- [ ] 个人中心协议、退出登录和注销入口可达。
- [ ] 注销存在未结交易时失败关闭并给出处理入口。
- [ ] AppSecret、支付密钥、供应商Key不出现在前端、Git或协议文件。
- [ ] DEV/TEST/STAGE/PROD正式依赖和域名映射经过本地门禁。
- [ ] 真实浏览器/微信开发者工具完成授权、拒绝、重新授权和协议升级验证。

## 七、仍需正式发布前确认

- 小程序在微信公众平台登记的正式名称。
- 充值供应商实际签约主体和数据处理说明。
- 备案信息及是否需要在前台展示。
- 最终法律审查意见。
