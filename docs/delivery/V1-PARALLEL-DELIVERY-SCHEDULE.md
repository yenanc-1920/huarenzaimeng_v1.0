# V1 后续并行交付安排

## 并行原则

- 环境故障与业务开发分线；非里程碑不触发云构建。
- 同一文件同时只允许一个角色写入。
- 每批只关闭冻结范围，不因单个问题扩成新架构。
- 外部凭据、真实金额、数据库执行均单列授权，不阻塞本地实现。

## 批次与责任

### 批次 A：候选归档与基线冻结（当前）

- 总控：变更清单、清理边界、逻辑提交、统一门禁。
- 产品/前端：需求、协议、高保真、页面合同。
- 后端/架构：技术设计、环境变量、迁移与接口清单。
- 安全：仅评审新增决策的基本安全底线。

依赖：无。可并行。

### 批次 B：协议、登录与个人中心

- 小程序：协议勾选、官方隐私授权、协议查看、注销入口和状态。
- 后端：同意记录、注销申请、会话撤销、保留期状态。
- 产品/法务：最终小程序名称、协议终稿、微信隐私指引配置。

依赖：批次 A 文档冻结。前后端可按固定 DTO 并行。

### 批次 C：真实身份与交易适配器

- 微信登录适配器、微信支付适配器、赢啦适配器分别独立开发。
- 默认关闭，全部先以固定 Fake/官方样例完成合同测试。
- 真实联调必须逐笔由用户操作并授权。

依赖：批次 B 身份合同；支付与赢啦可以并行，真实联调串行。

### 批次 D：MySQL 5.7 与视觉验收准备

- 数据库：只准备空库 V1 到当前版、现存版本到当前版、可重入与失败恢复脚本；不连接云库。
- 视觉：生成 16 个小程序页面和 21 个后台页面的截图验收矩阵。

依赖：候选 SHA 冻结。两线可并行。

### 批次 E：里程碑验收与环境晋级

- 本地全量门禁一次。
- DEV 到 TEST 到 STAGE 单向晋级；STAGE 经用户批准完成一笔最小真实交易。
- PROD 仅在 STAGE 通过后配置并由用户发布小程序版本。

依赖：前四批本地 GO；环境与真实金额授权。必须串行。

## 暂缓版本

- 手机号 KMS/密文迁移、细粒度职责分离、增强限流、自动容灾备份、多供应商、真实外汇、促销和复杂税务。
