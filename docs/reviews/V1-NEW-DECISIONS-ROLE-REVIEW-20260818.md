# V1 新增确认内容角色评审（2026-08-18）

## 结论

- 本地需求、设计与开发：`GO_FOR_LOCAL_DEVELOPMENT`
- 真实微信、赢啦联调：`NO-GO`，直到适配器、环境秘密和人工小额联调完成。
- 生产上线：`NO-GO`，直到协议授权链、手机号最小访问控制及真实联调证据闭合。

## 已接受的产品决策

1. 唯一 `SUPER_ADMIN` 可由同一账号创建、提交、审核和发布；普通角色仍保持职责分离。
2. V1 为履约允许数据库保存完整手机号明文；后续版本迁移为 KMS/密文。
3. 四环境共用一个小程序 AppID，但服务、数据库、账号和秘密必须隔离；生产包构建时固定生产 API。
4. 定价默认值只用于后台草稿和试算预填；保存和启用仍由 `SUPER_ADMIN` 显式执行。
5. 赢啦金额、状态、回调和号码规则已经业务方书面确认；真实适配器仍须以这些规则实现并完成一笔人工小额证据。

## P0 基本安全线

### P0-01 手机号明文

- 仅存履约专用字段/表，不进入通用 JSON 快照。
- 后台、公开 DTO、日志、异常、outbox、审计和导出只显示掩码或摘要。
- 读取权限限于履约服务；记录访问审计，并按隐私政策保留期删除或匿名化。
- 非生产环境只使用明确授权的测试号码。

### P0-02 登录协议与隐私授权

- 用户协议和隐私政策均默认不勾选；用户主动同时勾选后才可登录。
- 自有勾选不能替代微信官方隐私授权流程。
- 记录协议版本、接受时间及主体；拒绝授权不影响无需身份的基础浏览，下单前必须完成必要同意。

### P0-03 真实交易

- 微信支付、退款和赢啦充值默认关闭；缺配置必须失败关闭。
- 任意金额、币种、SKU、号码、签名或终态不匹配均进入 `UNKNOWN/A110`，不得自动重充、换渠道或退款。
- 每笔真实金额操作由用户逐笔操作或批准。

## P1 收口项

- `SUPER_ADMIN` 自审例外必须是窄例外；每一步仍保留独立幂等键、版本、原因、时间和不可变审计。
- 定价默认值使用比例小数存储并带版本、生效时间；不得由后端静默补齐或自动启用。
- 正式小程序构建发现非生产 API 根地址应直接失败。
- 环境 JSON 仅含键名和占位符，不含 AppSecret、API Key、密码、私钥或证书正文。

## 边界说明

- 本评审不重新审查旧需求，不新增角色审批层。
- 本地测试、Fake、构建成功不等于真实微信、赢啦、MySQL 或生产证据。
