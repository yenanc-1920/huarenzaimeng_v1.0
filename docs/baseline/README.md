# 华人在孟唯一项目基线

## 1. 权威声明

`docs/baseline/` 是“华人在孟”项目唯一当前权威信息入口。所有角色开始工作前必须先读本文件、`00-项目总览与当前状态.md` 和任务对应专题文件。

本目录之外的需求、设计、技术、计划、交接、事故、验收和评审文件，自本基线生效后统一视为：

- 来源材料；
- 历史过程；
- 批准或授权记录；
- 运行证据或附件。

它们不再独立产生新的执行约束。发生冲突时，以本目录为准；本目录未覆盖的内容必须登记为缺口，不得从多个旧文件中自行拼接结论。

## 2. 必读顺序

1. `00-项目总览与当前状态.md`
2. `01-治理权限与变更规则.md`
3. `02-角色职责与通讯.md`
4. 按任务读取一个或多个专题：
   - 产品／需求：`03-产品需求与业务规则.md`
   - UI／体验：`04-UI与交互基线.md`
   - 架构／集成：`05-技术架构与外部集成.md`
   - 开发：`06-开发工程与代码约束.md`
   - 测试／证据：`07-质量门禁与证据边界.md`
   - 部署／运维：`08-环境部署与运维.md`
   - 排障：`09-问题台账与经验.md`
   - 调度／计划：`10-版本计划与任务台账.md`
5. 需要追溯时才读 `11-来源与历史映射.md` 指向的旧文件。

## 3. 修改规则

- 一个主题只允许一个权威正文文件。
- 所有调整只修改本目录中的对应文件，并同步 `CHANGELOG.md`。
- 新问题必须有唯一 ID、责任角色、状态、证据路径、下一动作和关闭条件。
- 旧文件原则上不再修订；确需补证据时，只增加证据并在本目录登记，不得形成平行规则。
- 需求、架构或风险取舍必须记录批准人；资金、生产、密钥、破坏性数据库操作和重大需求取舍仍需南哥确认。
- 文档中的 AppSecret、token、私钥、完整手机号、一次性 code 和可复用凭据一律禁止。

## 4. 证据等级

从低到高区分：`STATIC`、`LOCAL_TEST`、`BUILD`、`CONTROLLED_RUNTIME`、`REAL_PROVIDER`、`REAL_DATABASE`、`PRODUCTION`。

低等级证据不得外推为高等级结论。Fake、H2、本地构建和静态扫描不能证明真实微信、真实数据库、真实资金或生产可用。

## 5. 轻量核验

修改本目录后执行：

```powershell
node tools/check-project-baseline.mjs
```

该命令只检查基线文件、执行头、统一入口、问题台账字段和敏感值形态，不运行构建、全量测试或部署。
