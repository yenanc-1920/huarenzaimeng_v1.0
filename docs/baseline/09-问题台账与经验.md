## 防复发经验

1. 先记录外层稳定错误，再在同版本、同实例、同参数下用最小探针定位底层原因。
2. TLS 问题不得连续猜补丁；必须区分 PKIX、hostname、代理、DNS、reset 和客户端差异。
3. CloudBase 将目标域名解析到 `169.254.10.1` 并返回自签证书时，先核对官方 SafeLink/云调用配置，不信任动态证书。
4. HTTP 只允许在官方 CloudBase DEV SafeLink 精确边界内使用，不得外推为公网 HTTP 或通用 TLS 降级。
5. 发布状态、健康状态、实例版本和业务成功是四类不同证据。
6. 微信 code 一次性使用，重试获取新 code；不得记录或复用旧 code。
7. Flyway 失败与业务代码失败分离；不 repair、clean、baseline、猜测续跑或自动重试。
8. Windows PowerShell 调用 Maven 时，每个 `-D...` 参数必须作为完整字符串传入；执行前检查仓库是否存在 wrapper，命令解析失败不得算测试结果。
9. 全量门禁只在明确进入发布链时运行；小问题默认定向测试。
10. Docker 首次缓存填充可能更慢，只有下一次同 scope 热缓存才证明优化收益。
11. 角色回传若与任务不符或退化为初始化话术，不得作为终态，必须回读证据或由空空收口。
12. 微信登录包含“创建会话”和“确认会话”两次请求，不等于重复调用`code2Session`；只有创建会话请求消耗一次性code。
13. 网络面板证据不得展开token、code、session_key或完整响应；误展开后按凭据暴露处理，禁止复制、提交或复用。
14. 商品目录和运营商支持集均可能在切换期间短暂重叠有效；公开目录与报价必须统一选择“版本号最大的当前有效支持集＋该支持集下版本号最大的当前有效目录”，不得各自实现不同的选择范围。
15. 页面与API客户端不得在同一用户动作中连续复拉并重复校验同一目录；保留靠近报价POST的唯一客户端校验，并由后端继续执行最终权威校验。
16. 商品名称、权益说明和有效期文案是展示快照，不是商品或价格身份；客户端不得因这些文案表示差异阻断同一版本的报价，但商品、支持集/目录版本、面额、类型和价格版本仍须严格失败关闭。
17. 网络面板“目录GET成功但报价POST未出现”不等于目录匹配失败；必须检查POST参数求值前的身份门禁。不同异常不得由同一个catch统一翻译为商品更新。
18. 当前有效价格可能因历史或切换数据短暂重叠；公开目录与报价必须复用同一稳定选择规则。不得由目录选最新、报价却要求物理仅一行，也不得在未冻结规则时静默任选价格。
19. 项目服务器运行与部署平台是“微信云托管”，不得写作或推断为“腾讯云服务器／腾讯云部署”；`CloudBase` 仅作为微信云托管现有控制面、工具标识或证据原文保留，版本、实例、控制台与日志时间均按微信云托管证据记录。
