# 技术架构与外部集成

## 总体架构

- 微信小程序与 Vue 运营后台通过项目 API 访问后端。
- Java 17／Spring Boot 后端负责身份、目录、报价、订单、支付、充值、内容和后台领域。
- MySQL 5.7＋Flyway 管理持久化演进；外部能力通过正式端口/适配器隔离。
- 业务状态采用幂等、单调推进、不可变快照、outbox、任务租约和 UNKNOWN 恢复。

## 环境

- DEV、TEST、STAGE、PROD 服务、数据库、账号、域名、秘密和发布链隔离。
- 环境变量模板只记录键和占位符，实际秘密只存在于平台受控配置。
- 未配置、错配或能力不可达时启动或请求失败关闭，不产生 Fake 成功。

## 微信身份

- 默认模式为固定 HTTPS：`https://api.weixin.qq.com/sns/jscode2session`。
- 仅 CloudBase DEV 冻结环境可显式使用固定 SafeLink HTTP：`http://api.weixin.qq.com/sns/jscode2session`。
- SafeLink HTTP 同时要求：环境名 `dev`、冻结 TCB 环境 ID、显式 transport mode、固定 host/path、唯一精确 `x-openapi-rule: bypass`。
- 禁止 redirect、代理、fallback、应用重试、关闭 TLS/hostname 校验或导入动态自签 CA。
- 非 CloudBase、非 DEV、错环境、错 host/path/header 一律失败关闭。

## 微信支付与 WINLA

- 真实适配器默认 disabled，且配置、身份绑定、回调验签、金额和状态必须全部通过才可启用。
- 微信支付必须绑定预期 AppID、商户号和允许的平台证书序列。
- WINLA 回调不伪造其未提供的 SKU/手机号证据，只绑定提交前不可变内部快照。
- 未知结果只查原单，禁止重复资金动作。

## 匿名报价与建单

- `POST /buyer-auth/v1/anonymous-sessions` 是唯一匿名交易会话签发入口；请求严格绑定 `requestRef`、`guestRef` 和当前协议同意，服务端生成高熵随机 `anonymousSubjectRef` 与 Bearer token，只持久化 token 摘要。
- 匿名会话绝对有效期24小时，不续期、不刷新；`guestRef` 不是认证凭据，不得由客户端自报 `subjectRef`、主体类型或归属关系。
- 交易过滤器只允许匿名主体调用 `POST /buyer-api/v1/quotes` 与 `POST /buyer-api/v1/orders`。两者的幂等范围、请求指纹、Quote、Order、号码摘要和价格快照均绑定同一 `anonymousSubjectRef`。
- 创建订单必须在同一事务锁读同一匿名主体的未过期 Quote，并重验目录、商品和价格权威状态；跨主体、过期、已消费、冲突或结果未知均失败关闭。
- 订单列表、订单历史、账户、退出和注销只接受 BUYER；匿名主体不得枚举、认领、迁移或合并订单。
- `POST /buyer-auth/v1/session/logout`兼容微信云托管`callContainer`产生的无请求体或空JSON对象；query、非对象及带字段对象仍以`LOGOUT_REQUEST_INVALID`拒绝。
- 注销清理调度在release环境默认开启并按30秒间隔认领任务；未结交易失败关闭并延后重试，不能绕过交易阻塞直接关闭账号。
- 最终关闭账号时删除会话及微信支付身份，并将旧微信身份唯一键替换为不可逆墓碑摘要；同一微信后续只能建立新的buyer身份，不能关联旧subject或旧交易。
- release个人订单读取以当前内存中的有效BUYER token为唯一客户端登录门禁；旧`projectSessionProjection`只属于历史恢复投影，不得否定真实BUYER会话。
- 本合同只关闭无资金主链的匿名报价与建单，不启用或放宽微信支付、WINLA、W/U/D/R/L/Ledger 及真实资金能力。

## 数据与迁移

- Flyway 自动初始化在发布链中受专用启动顺序控制；迁移失败不得 repair、clean、baseline 或猜测续跑。
- 自定义 `releaseFlyway` 必须把已冻结的 `hz.environment.database-name` 显式绑定为 Flyway `defaultSchema`；不得依赖平台注入额外 schema 环境变量。
- 真实迁移必须冻结目标身份、权限、备份/恢复、制品、RunId 和 PRE/MID/POST Oracle。
- 当前 MySQL 5.7 专用真实验证仍为 NOT_RUN。
- 公开目录与报价统一绑定“版本号最大的当前有效运营商支持集＋该支持集下版本号最大的当前有效商品目录”；仍有效的历史支持集或目录不得造成商品或价格误判为不唯一。
- DEV repeatable 样例若用于匿名报价，必须同时提供当前有效支持批次、对应运营商的 `SUPPORTED` 成员关系及该支持集下当前有效目录；只具备商品、渠道和价格数据不构成可报价权威数据。
- 公开目录与报价对同一商品的当前有效价格统一选择 `effective_from` 最大者；时间相同时以 `price_version_ref` 最大者稳定裁决。历史或切换期重叠的 `ACTIVE` 价格不得导致目录与报价选择不同，但创建订单仍按 Quote 冻结的精确价格版本重验。
- P012 创建报价前只允许 `api.createQuote` 复拉并校验一次当前目录；页面不得在紧邻调用前重复复拉形成额外竞态窗口。目录或商品失效仍须在报价请求前失败关闭，报价服务继续作为商品有效性最终权威。
- 报价前客户端目录匹配只以运营商、支持集/目录版本、`productRef`、面额、商品类型和 `priceVersionRef` 等稳定身份字段失败关闭；`displayName`、`benefitText`、`validityText` 仅用于已选展示快照，不作为同一商品与价格版本的本地否决条件。
- 报价网络调用前必须具有有效 BUYER 或有效匿名交易会话；缺少、过期或错类型凭据属于身份门禁，不属于目录失效，目录稳定身份失败仍单独失败关闭。
