## 试运行范围控制

- “全部功能跑通”指 V1 已批准范围；V1.1/V1.2 不得借机进入当前候选。
- 非阻断 UI 微调、重构、性能提升和文档美化不打断业务闭环，统一进入试运行观察清单。
- 每个阶段集中形成一个候选和一次发布，避免“一处小改一次重型发布”。
- 阶段内发现问题仍按“定位→一次有界修复→定向验证→提交”处理；集中到候选窗口后再触发发布门禁。
- 真实资金和 PROD 发布分别单独请南哥确认；批准一次只覆盖冻结版本、明确金额、环境和 RunId。

## 后续版本

- V1.1：KMS/手机号密文、细化权限与保留期、运营效率、更多恢复与可观测性。
- V1.2：多供应商或更复杂路由、财务审批、自动化对账扩展，须另行需求批准。
- 未经南哥决策，不把后续版本内容提前塞入 V1。

## 调度节奏

- 小问题以分钟级定向修复为目标，不为每个小改主动触发小时级发布链。
- 功能分支提交和 DEV 合并分开决策；若合并会触发重型门禁，提前说明预计成本。
- 外部等待期间只监控状态，不追加测试、重发或无界修改。
- 任何角色发现不影响当前业务闭环的事项，只登记不插队；空空负责控制在制任务数量和候选发布窗口。
