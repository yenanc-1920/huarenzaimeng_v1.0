# 质量门禁与证据边界

## 测试策略

- 默认只做与问题直接相关的定向测试；不得为小问题擅自扩展为全量测试。
- 只有明确进入会触发发布的集成流程且获准时，才执行对应发布门禁。
- 测试终态必须报告 TOTAL、PASS、FAIL、ERROR、SKIP、NOT_RUN。
- 命令解析失败、依赖不可用或环境阻断均不得记为测试失败或 PASS。
- 全功能跑通采用“功能域定向验证＋关键业务旅程端到端验证”，不因单个小改重复执行全量门禁。
- 同一批修复尽量合并为一个候选版本；发布门禁只在该候选进入环境晋级时执行一次。

## 试运行放行门槛

- V1 功能清单逐项具有明确的 PASS、受控降级或经南哥批准的延期结论，不允许 UNKNOWN 混入发布。
- 登录、报价、支付、充值、订单查询、UNKNOWN 恢复、退出/重登录和注销申请形成真实端到端证据。
- 后台至少覆盖内容、目录、定价、订单/异常处置和审计等试运营必需能力。
- P0=0；P1 必须有负责人、规避措施、观察指标和截止时间。
- TEST/STAGE/PROD 使用同一冻结候选；发生代码漂移重新冻结，不沿用旧结论。
- 真实外部能力、真实数据库、真实资金、视觉和生产证据分别登记，不相互冒充。

## 证据边界

| 证据 | 能证明 | 不能证明 |
|---|---|---|
| STATIC | 文件、合同、配置结构 | 代码可运行、真实外部行为 |
| LOCAL_TEST | 指定本地逻辑 | 真实数据库、微信、资金、生产 |
| BUILD | 可编译和形成制品 | 页面像素、服务就绪、业务成功 |
| CONTROLLED_RUNTIME | 指定环境与版本的受控行为 | 其他环境或生产稳定性 |
| REAL_PROVIDER | 指定外部供应商链路 | 资金结算完整性或生产长期稳定 |
| REAL_DATABASE | 指定数据库执行结果 | 其他实例、备份恢复或生产 |
| PRODUCTION | 指定版本生产证据 | 未覆盖场景的普遍正确性 |

## 固定对象

受控测试前冻结提交、文件清单、SHA、参数、环境身份、分母和 RunId。对象发生漂移立即停止，不能用相似共享树替代。
