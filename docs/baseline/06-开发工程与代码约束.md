# 开发工程与代码约束

## 工作方式

- 固定仓库：`E:\workspace\huarenzaimeng`。
- 开始修改前记录分支、HEAD、Git 状态和目标文件；不清理来源不明改动。
- 一个问题一个唯一 ID，一次只修一个首因。
- 修改必须最小、有界、可回退，不顺手重构无关模块。
- 编辑使用受控补丁；提交只暂存本问题精确文件。

## 分支与提交

- 开发在 `codex/v1-delivery-recovery` 或经批准的 `codex/` 分支完成。
- `dev` 是 DEV 集成入口，`deploy/dev` 只由门禁成功后推进。
- 提交信息应说明 fix/test/ci/docs 的真实目的。
- 推送前执行定向测试与 `git diff --check`；禁止强推覆盖他人历史。
- 本地提交成功后自动推送当前工作分支；属于已批准DEV集成范围的提交同步推进`dev`并等待既有门禁，生产发布、强推及其他越权外部写入仍须单独确认。

## 后端

- Java 17；配置缺失、环境错绑、身份不一致和外部能力不可达必须失败关闭。
- 公开错误只返回稳定分类；不得记录 secret、code、session_key、完整 query、原始供应商响应或完整手机号。
- 金额使用整数 minor unit 与显式币种；业务状态单调、幂等、可审计。
- 外部 HTTP 固定 scheme/host/path/method/参数合同；禁止任意 endpoint、redirect、通用代理、fallback 和无界 retry。

## 前端

- 页面只消费正式 DTO/状态合同；不得在发布构建中启用 fixture、sandbox 或环境切换。
- 构建后必须检查微信 AppService 模块加载、路由、静态资源和目标环境。
- 微信小程序构建必须开启 JS 压缩与组件按需注入；全部图片和音频静态资源合计不得超过代码质量扫描的 200 KB 建议线，主包应保持低于 1.5 MB 建议线。
- 日志、错误提示和埋点不得包含秘密、完整手机号或身份原始值。

## 配置与秘密

- Secret、token、私钥、证书私钥、真实手机号和一次性 code 禁止进入 Git、文档、截图和前端变量。
- 环境变量“存在”不代表能力获准；必须同时满足基线开关和运行身份门。
