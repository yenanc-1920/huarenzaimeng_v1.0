# UI 与交互基线

## 当前范围

- 小程序：`pages.json` 当前登记 18 个正式页面。
- 运营后台：21 个高保真 frame／工作区。
- 正式页面必须使用业务 DTO 和业务化状态，不得回退到 Sandbox 文案或测试入口。
- `pages/support/case.vue` 未登记路由、无正式导航引用，且其 `/support/case` 客户端读取没有对应买家 API；当前视为非执行残留，不计入 V1 页面。V1 客服入口以微信 `open-type="contact"` 为准，未经需求批准不得把该残留页面接入正式流程。

## 通用交互

- P010 手机号输入框直接展示并接收 `01xxxxxxxxx` 共11位本地格式，占位示例为 `01712345678`；不得要求用户自行去掉前导 `0`，错误提示须明确“以01开头的11位孟加拉手机号”。
- P010成功识别运营商后，在运营商名称前展示与`operatorCode`固定映射的运营商Logo图片；不得继续使用“号码”等文字方块冒充Logo。
- 小程序按钮、列表项、分类和Tab等交互元素内的文字必须垂直居中；多行正文仍按正文排版，不强制改成居中对齐。
- 页面必须覆盖 loading、empty、ready、disabled、denied、unknown、failure 和 retry/recovery 等适用状态。
- 登录与订单恢复分离；登录不承担订单找回语义。
- 登录页使用单一合并协议勾选项；微信隐私授权按平台流程单独触发。
- P024登录态身份卡只显示头像和用户名，不显示头像来源、默认头像说明、昵称授权说明或登录能力说明；未登录态仍可显示登录入口提示。
- P024无用户头像时使用无文字的默认图案图片，不再以“人”等文字充当头像。
- P001双时钟刷新按钮文字必须在胶囊框内水平、垂直居中；P042资讯分类文字必须在各自分类框内水平、垂直居中。
- 用户协议和隐私政策正文滚动时，顶部返回区域固定在可视区域，不随正文被顶出页面。
- 由“我的”或“我的订单”触发登录时，登录成功后返回原触发页面，不固定跳转首页；返回目标必须使用固定内部白名单。
- 游客浏览与需要身份的操作有明确边界；个人信息入口允许触发登录。
- 错误结果可撤销或返回，错误文案使用稳定业务含义，不暴露内部异常和秘密。
- 导航、返回、TabBar、页面路径和 AppService 模块必须在微信开发者工具真实加载验证。

## 视觉证据

- 构建、路由、静态追踪和 AppService 加载不等于像素验收。
- 当前视觉状态：小程序18个已登记页面和后台21 frame均为 `NOT_EVIDENCED`；小程序为 `NO_REAL_DEVICE_EVIDENCE`。
- 正式验收必须冻结 build、pageId、viewport、数据状态和截图时间，进行基线对比并人工签核。
- 高保真源和截图矩阵保留在历史/资源目录，权威状态与变更要求只在本文件和问题台账维护。

## 变更要求

任何页面、字段、状态或流程调整，必须同时说明产品规则、API/DTO、埋点或日志、安全隐私、测试和截图矩阵影响；只改视觉稿或只改代码均不能单独闭环。
