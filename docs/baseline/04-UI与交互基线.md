# UI 与交互基线

## 当前范围

- 小程序：16 个业务页面。
- 运营后台：21 个高保真 frame／工作区。
- 正式页面必须使用业务 DTO 和业务化状态，不得回退到 Sandbox 文案或测试入口。

## 通用交互

- 页面必须覆盖 loading、empty、ready、disabled、denied、unknown、failure 和 retry/recovery 等适用状态。
- 登录与订单恢复分离；登录不承担订单找回语义。
- 登录页使用单一合并协议勾选项；微信隐私授权按平台流程单独触发。
- 游客浏览与需要身份的操作有明确边界；个人信息入口允许触发登录。
- 错误结果可撤销或返回，错误文案使用稳定业务含义，不暴露内部异常和秘密。
- 导航、返回、TabBar、页面路径和 AppService 模块必须在微信开发者工具真实加载验证。

## 视觉证据

- 构建、路由、静态追踪和 AppService 加载不等于像素验收。
- 当前视觉状态：小程序 16 页和后台 21 frame 均为 `NOT_EVIDENCED`；小程序为 `NO_REAL_DEVICE_EVIDENCE`。
- 正式验收必须冻结 build、pageId、viewport、数据状态和截图时间，进行基线对比并人工签核。
- 高保真源和截图矩阵保留在历史/资源目录，权威状态与变更要求只在本文件和问题台账维护。

## 变更要求

任何页面、字段、状态或流程调整，必须同时说明产品规则、API/DTO、埋点或日志、安全隐私、测试和截图矩阵影响；只改视觉稿或只改代码均不能单独闭环。
